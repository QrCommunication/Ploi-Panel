# Scripts de déploiement : édition par site et modèles globaux

- **Serveurs → site → Déploiements → Script** : consulter et modifier le texte complet du script de ce site. L'éditeur occupe l'écran, emploie une police monospace et protège les brouillons non enregistrés. **Enregistrer** ouvre immédiatement la vérification PIN ou biométrique, puis l'API Ploi `PATCH /servers/{server}/sites/{site}/deploy-script` est appelée ; la réponse est relue avant d'afficher une confirmation. Cela **ne lance aucun déploiement**.
- **Déploiements** (onglet principal) : créer, modifier et supprimer des modèles de script locaux chiffrés, séparés par profil Ploi. Choisir les sites par cases à cocher sur les serveurs et les pages de sites ; la sélection survit au changement de page/serveur. Aperçu du texte résolu sur le premier site. L'action **Appliquer le texte aux sites choisis** déclenche la vérification PIN ou biométrique à ce moment-là, pas lors du choix des cases. Aucune action distante n'a lieu si elle échoue.
- Variables facultatives : `{{domain}}` (domaine validé et protégé par apostrophes shell), `{{server_id}}`, `{{site_id}}`. Utiliser `{{domain}}` hors de guillemets déjà ouverts ; toute variable inconnue est refusée. Les scripts sont limités à la taille acceptée par l'API Ploi. Relire les chemins, services et commandes propres à chaque site avant d'appliquer.
- Traitement : un GET préalable est effectué sur tous les sites retenus, puis les PATCH sont séquentiels et chacun est suivi d'un GET de contrôle. Une lecture initiale échouée bloque **tous** les PATCH. Les résultats distinguent réussite relue, demande non vérifiable, échec et non-modification ; en cas de limitation HTTP 429, la suite est arrêtée sans nouvelles requêtes. Un échec après le début peut laisser une **application partielle** : inspecter les résultats par site et ne pas relancer aveuglément. Le batch ne déclenche pas de déploiement et ne prétend pas être atomique côté Ploi.
- La suppression d'un modèle local ne modifie pas les scripts déjà enregistrés sur Ploi. Les modèles sont inclus dans la sauvegarde de configuration chiffrée version 2 ; les archives v1 restent importables.

**À confirmer sur appareil et compte Ploi autorisé :** rendu dans les formats compacts/pliables, prompt biométrique et lecture/écriture réelles des scripts (aucune API globale non documentée n'est supposée). Ne pas exécuter sur des sites de production sans validation des scripts et accord d'exploitation.
